What v0.1 checks

Every part a plugin can ship, not only the mod.

A plugin can carry mods, shell hooks, MCP servers, and instructions for the model. Each one can hide a payload, so each one is read with rules written for it.

Mods

hooks/hooks.json → modules · *.ts *.tsx *.js

Parsed with the TypeScript compiler. Every call on $ is resolved to its path, through aliases like const { fetch: send } = $.http and renamed hook parameters, then traced from where data is read to where it goes.

  • CriticalSettings, secret env vars, credential files or the conversation flowing into $.http.fetch, $.process or $.mcp.call
  • Criticaltool.call hooks that append commands to the model’s Bash calls
  • Criticalprompt.compose text that tells the model to hide something and insert or send something
  • Hightool.check hooks that answer allow for Bash, Write, Edit or MCP tools
  • HighComputed $[name] access, eval, new Function, base64 that decodes to a URL or command
  • HighWrites to .git/hooks, shell rc files, .claude/settings.json, CLAUDE.md
  • HighChanging NODE_OPTIONS, PATH, ANTHROPIC_BASE_URL and similar for every later command
  • HighRequests to tunnels, paste sites, webhooks and raw IPs; shell or computed commands
  • MediumDate checks (time bombs) and CI or sandbox checks used to behave well under analysis
  • MediumRewriting file edits or URLs; redrawing permission or confirmation UI; minified source

Shell hooks

hooks.json → hooks · *.sh *.py
  • CriticalDownload piped into a shell, reverse shells, decode-and-run
  • CriticalA command that reads ~/.ssh or ~/.aws and talks to the network
  • HighHook scripts that approve permission requests themselves
  • HighPersistence through cron, launch agents or shell rc files

Skills, agents, commands

SKILL.md · agents/ · commands/ · CLAUDE.md
  • CriticalInstructions to conceal plus a payload to run, send or insert
  • HighHidden HTML comments carrying instructions; zero-width, bidi and tag characters
  • High“Ignore previous instructions”, code-insertion and exfiltration requests
  • Mediumallowed-tools that grants unrestricted Bash

MCP servers

.mcp.json · plugin.json → mcpServers
  • Mediumnpx or uvx packages with no pinned version, so every start runs the latest release
  • MediumRemote servers over plain HTTP; servers started through a shell

Packages and files

A permission list, written from the code

Next to the findings, every scan lists what the plugin can do, with the hosts, commands and variables it names. Compare that list with the plugin’s description. A theme that reads your settings and makes network requests needs an explanation.

Each plugin also gets a SHA-256 of its files, so a result is tied to the exact version that was scanned.

How a scan runs

Five steps, all of them reading.

  1. Unpack

    The archive stays in memory. Sizes are checked before anything inflates, so a zip bomb is refused. GitHub archives come only from codeload.github.com.

  2. Inventory

    Find every .claude-plugin/plugin.json, then sort each file by role: mod, shell hook, MCP server, skill, agent, command or script.

  3. Resolve

    Parse each module, follow aliases back to $, and read hook matchers such as { tool: 'Bash' }.

  4. Trace

    Mark what comes from sensitive sources and follow it through variables to network, process and file sinks.

  5. Score

    Weigh findings by severity, damp repeats, lower the severity of quoted examples and unimported test files, then give a verdict.

Verdicts

Four answers, and none of them is “safe”.

Static analysis can show that something is wrong. It cannot prove that nothing is, so the best result says exactly that.

Malicious indicators

any critical finding

Patterns typical of malware. Do not install.

High risk

any high finding, or score ≥ 40

Capabilities that need a close read before installing.

Review recommended

any medium finding, or score ≥ 8

Nothing clearly malicious; some behaviour deserves a look.

No known issues found

otherwise

No known pattern in this exact SHA-256.

The score runs from 0 to 100. Critical findings weigh 60, high 25, medium 8 and low 2. Repeats of the same rule count for less each time, so one noisy rule cannot dominate.

v0.1 scope

What this version does, and what it leaves for later.

In v0.1

  • Static analysis of mods, shell hooks, MCP config, skills, agents, commands, scripts and packages
  • Capability manifest with hosts, commands, env names and tools for each plugin
  • Findings with file, line, snippet and rule id; a 0–100 score and a verdict
  • Web app: paste a GitHub URL (repo or folder) or upload a .zip up to 10 MB
  • CLI for folders, zips and GitHub, with JSON output and --fail-on for CI
  • Multi-plugin repos: a marketplace repo gets one report per plugin

Not yet

  • Sandbox run of a mod against a mocked $ with planted fake keys
  • LLM review comparing what the code does with what the description promises
  • Version diffs that flag a capability added in a later release
  • Data-flow for Node APIs in MCP servers; they are listed as capabilities only
  • Scope-aware tracing; v0.1 follows variables by name, so deliberate obfuscation can slip past
  • A pre-install gate inside Claude Code, and a public database of results
